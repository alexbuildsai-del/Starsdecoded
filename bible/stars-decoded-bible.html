Overview

What Stars Decoded is, who it is for, and exactly how a report gets made. Everything on this page traces to the repository at commit 0d7bf7a or to the Notion product log.

The one-paragraph version

Stars Decoded sells a psychological self-knowledge report built on real astronomical calculation. You give it a birth date, time and place. The backend computes actual planetary positions locally, then feeds that structured chart data through a chain of language-model calls that write a 2,000–2,800 word interpretation covering how you work, how you love, what you are good at, and what will always be hard. It is deliberately analytical rather than mystical: no predictions, no fate, no karma. The report is the product — not a subscription, not a dashboard.

The one-page version

Who it is for. The self-knowledge audience — the people who already take Myers-Briggs and Enneagram seriously. The Notion GTM page frames the bet precisely: “You're not selling astrology. You're selling a structured self-knowledge report that happens to use planetary data.” A second segment, parents wanting to understand their child, is called the biggest differentiator but is not built yet.

What makes it different. Two things, in the intended positioning. First, the chart maths is real computation rather than a language model guessing where the planets were. Second, the writing is grounded in a pre-generated meaning library — a database of canonical per-placement and per-aspect interpretations that the model must synthesise across rather than invent from. That constraint is what stops the output drifting into generic horoscope prose.

How it makes money. It does not yet. There is no payment code in the repository at all. Prices exist as copy on the landing page and as hypotheses in Notion.

How a report is generated

Every step below is a real code path. The two AI stages are the only places a model is called.

Opinion

The parse step is the weakest link. Every section parser catches its own failure and silently returns the raw model output as a string instead of the structured object — which is why several types in aiInterpretation.ts are Section | string. A malformed response does not error, it degrades, and the report page has to cope. Since the calls set no response_format, there is nothing forcing valid JSON in the first place. Turning on structured outputs would remove a whole class of silent failure for about ten lines of change.

Design system

Every value on this page is read from web/src/index.css. Swatches are painted with the real hsl() token and the hex underneath is computed by the browser from that paint, so it cannot drift from the source.

Read this first

Astra ships dark only. There is no light theme — the .dark block is a byte-for-byte duplicate of :root, and html{color-scheme:dark} is hard-set. Anywhere below that a token is shown on light paper, that is this document's surface, not the product's. The dark stages show the real thing.

Colour roles

Twelve semantic roles, all defined as bare H S% L% triples and wrapped in hsl() by the Tailwind theme layer. Radix-style role naming (background / foreground / muted / accent) carried over from shadcn.

Chart colours

Five, used by the chart wheel and the aspect lines. Note there is no green and no semantic success colour anywhere in the system.

Opinion — the useful finding

Inference is not your cost driver and never will be at this price point. Even at the pessimistic token price with every section maxed out, the model costs about 0.7% of a €24 sale, and Stripe costs roughly four times more than the AI does. Two things follow.

First, stop treating token budgets as a cost constraint. If a longer or better report converts even marginally better, it is free. The current 500-token ceiling on synastry sections is almost certainly costing you quality to save fractions of a cent.

Second, the only number that decides whether this business works is customer acquisition cost, and it is completely unknown. At 97% gross margin you can afford roughly €23 of CAC before a sale stops paying for itself. That single figure — not price — is what the first campaign needs to measure.

Why this order

From the product log: Overview leads because it establishes shape before detail. Core Triad stays early as the most familiar entry point. Career and Relationships come before the trait-level material because concrete life domains land first and make the abstractions legible afterwards. Focus closes because it is the only actionable section and it needs everything above it.

What it deliberately does not claim

Enforced in the system prompt on every section:

  • No predictions, no fate, no personality certainty, no past lives, no future events
  • No karmic claims and no mystical certainty
  • No generic trait lists
  • It may not invent a per-placement meaning, or contradict one supplied by the meaning library
  • Planets are not named in summary prose — the psychological reality is described instead
  • No mention of being an AI, of a prompt, of a word count, or of the instructions
  • Banned constructions: em-dashes as clause connectors, “it's worth noting”, “at the end of the day”, “navigating”, “not just X but Y”, three-part adjective stacks

Sample — Marie Curie, sections 1 and 5

Caveat

This is a real validated output, scored 9.4/10 in Session 1 testing, and it is the only full sample that exists. But it was produced by the pre-ship prompt revision — plain-text output, lower token ceilings. The shipped prompts emit structured JSON. Treat it as representative of voice and depth, not of current output format.

1 · Chart Overview

Your chart is built around one thing: meaningful work that transforms. Everything else—intimate relationships, play, personal comfort—is secondary.

You have four planets concentrated in your 10th house of career, your chart ruler Saturn also sits there, and your rising sign (Capricorn) aligns with this focus. Most people juggle multiple life areas equally. Your chart points in one direction.

Two zones are notably quiet: your 8th house (intimacy) and 5th house (creativity). This doesn't mean you're incapable of these things. It means they're not primary drives for you. Intimacy will always feel harder than work. Play feels optional.

Most people spread their energy across multiple life areas. You concentrate yours. This gives you the psychological stamina to pursue what defeats most people. The cost is that you sacrifice things other people don't have to.

5 · Chronic Pattern — showing the “can't fix, only manage” framing

The Pattern You'll Always Navigate: Difficulty with Intimacy

Your chart doesn't ask you to prioritize intimate partnership equally with career. Your 8th house (intimacy) is quiet. Your 10th house (career) is crowded. This is your wiring.

You will always tend toward isolation or control in close relationships. You will always struggle to show vulnerability. This isn't changeable. It's structural.

But here's what matters: this becomes a problem only if you fight it or resent it. If you accept it and structure your life accordingly, it's fine.

How to manage: One vulnerability per week. One conversation where you admit struggle. Notice when you're isolating. That's your pattern activating.

Opinion

That excerpt is good — specific, unhedged, and it does the thing most astrology products refuse to do, which is tell someone a limitation is permanent and then make it useful. It is also the single best marketing asset you own, and it is sitting in a Notion page instead of on the landing page, which is exactly what your own GTM document says to do with it.

Opinion

Two things stand out. First, those empty-category fallbacks are a genuinely good piece of prompt engineering — most systems would emit a limp paragraph, this one turns absence into content. Second, 500 tokens is a hard ceiling of roughly 375 words per section, which is tight for material this dense. Given inference costs fractions of a cent, that ceiling is saving nothing and may be truncating output mid-sentence.

Post-processing

  1. Trim whitespace from choices[0].message.content, defaulting to "".
  2. Strip markdown fences with replace(/```json\n?|\n?```/g, "").
  3. JSON.parse inside a try/catch.
  4. Coerce every field defensively — non-strings become "", non-arrays become [].
  5. On any parse failure, return the raw string instead of the object.
Output contract — and what breaks it

There is no JSON schema and no validation layer. The contract is expressed only as prose inside each user prompt, and the shape checks are ad-hoc: Career and Relationships require exactly cards.length === 3 or the whole section falls back to raw text; every other section accepts whatever parses. Because malformed output degrades to a string rather than raising, a broken prompt produces a report that saves successfully and renders wrongly. Nothing is logged when this happens.

Version history

There isn't any

The prompt_templates table stores updatedAt and nothing else — no previous value, no author, no reason. Editing a prompt in the admin UI overwrites the row irreversibly. Git does not help either: all 85 prompts arrived in a single squashed port commit (646201f, “Port prompt defaults”), so there is no meaningful history there either. You currently cannot answer “what did this prompt say last week, and did the change help?”

Smallest fix that gives you history

Add one append-only table and one insert. Roughly twenty lines plus a migration:

prompt_template_revisions
  id            text primary key
  prompt_key    text not null
  system_prompt text
  user_prompt   text
  replaced_at   timestamp not null default now()
  replaced_by   text          -- Clerk user id from the admin guard
  note          text          -- optional "why" field on the admin form

In the PUT /admin/prompts/:key handler, insert the outgoing row before writing the new one. That gives you a diff view, an undo, and an answer to “which prompt version produced this report” if you also stamp the key set on reports. It also makes the existing repairStalePromptOverrides boot step recoverable — today it silently deletes overrides with no way to see what was lost.
